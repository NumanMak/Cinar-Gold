# Çınar Gold Arka Uç Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Statik mağazanın hesap, adres, favori, sipariş, stok ve bildirim verisini Supabase'e taşımak; yönetici tüm siparişleri tek panelde onaylasın; ödeme havale/EFT + WhatsApp olarak kalsın.

**Architecture:** Mevcut yerel (localStorage) uygulama `local` adaptörü olarak korunur; aynı **asenkron** arayüzü sağlayan yeni `supabase` adaptörü Supabase Auth ve PostgREST/RPC'ye `fetch` ile bağlanır (ek bağımlılık yok, CSP `script-src` değişmez). Fiyat, kupon ve stok kararları sunucu fonksiyonlarında (SECURITY DEFINER) verilir. Sayfalar yalnızca `ctx.api` arayüzünü kullanır.

**Tech Stack:** Supabase (Postgres, Auth, RLS, RPC), vanilla ES modules, Node 26 `node --test`, Python 3 (SQL/CSP/ürün araçları), Edge tarayıcı senaryosu.

**Spec:** `docs/superpowers/specs/2026-10-19-arka-uc-tasarimi.md`

## Global Constraints

- Tarayıcıya yalnızca proje adresi ve herkese açık `anon` anahtar girer; `service_role` anahtarı ve veritabanı şifresi depoya, tarayıcıya ve sohbete asla girmez.
- Müşteri `profiles.role` alanını değiştiremez; yönetici rolü yalnızca Supabase panelinden SQL ile verilir.
- Siparişler yalnızca `place_order`, `cancel_my_order`, `admin_set_order_status` fonksiyonlarıyla oluşur/değişir; `orders` ve `order_lines` tablolarına doğrudan INSERT/UPDATE/DELETE politikası yoktur.
- Fiyat ve kupon sunucuda hesaplanır: `price = round(gram x (gram22 x karat / 22) x (1 + işçilik) + taş bedeli, 10 TL'ye)`; kupon `CINAR10` = %10 (`round`).
- Kullanıcıya görünen metin Türkçe, her metin `t('...')` ile sarılı ve `assets/js/shop/i18n-en.js` içinde İngilizcesi vardır (`tests/i18n-coverage.test.mjs`).
- Metinlerde `—` ve `–` kullanılmaz; CSP `default-src 'none'` korunur, `connect-src` yalnızca `'self'`, `https://finans.truncgil.com` ve proje adresini içerir; `'unsafe-inline'`/`'unsafe-eval'` yok.
- Kullanıcı/sunucu metni DOM'a yalnızca `textContent` ile yazılır.
- Mevcut testler (135 birim, 28 tarayıcı adımı) `local` adaptörüyle yeşil kalır.
- Commit mesajları Türkçe, sonunda `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`. GitHub'a push yalnızca kullanıcı onayıyla.

## Review Focus

1. İki müşteri aynı anda son ürünü sipariş eder: yalnızca biri başarılı olur, stok asla negatif olmaz (Task 1, Task 6).
2. Tarayıcı `place_order`'a bozuk/negatif adet, bilinmeyen ürün, manipüle fiyat veya geçersiz kupon gönderir: sunucu reddeder ya da kendi fiyatını kullanır (Task 1).
3. Müşteri A, B'nin siparişini/adresini okuyamaz; müşteri kendini `admin` yapamaz; doğrudan `orders` INSERT'i reddedilir (Task 1, Task 6).
4. Supabase yanıt vermezse/ağ kesilirse sayfa çökmez, anlaşılır Türkçe/İngilizce hata gösterir ve sepet kaybolmaz (Task 4, Task 5).
5. Oturum süresi dolmuş veya geçersiz jeton: kullanıcı misafire döner, yarım yazılmış sipariş formu silinmez (Task 4, Task 5).
